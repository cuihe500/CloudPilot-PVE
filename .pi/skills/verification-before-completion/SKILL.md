# 完成前验证

## 硬规则

没有当前工作树上的新鲜验证证据，不得声称完成或通过。

## 验证步骤

1. **确定结论**：列出准备声称已经满足的行为和验收场景。
2. **选择证据**：为每个结论确定能直接证明它的命令或检查。
3. **执行检查**：先运行针对性测试，再运行仓库统一的 `make check`。
4. **读取结果**：检查完整输出、失败数量和退出码，不依赖摘要或以前的运行。
5. **检查变更**：查看 `git diff` 和 `git status`，确认没有越界修改、秘密、生成文件漂移或遗漏文档。
6. **对照规范**：逐项核对已批准 OpenSpec 和 `AGENTS.md` 的完成定义。
7. **报告事实**：列出运行过的命令、结果和未验证项。检查失败时报告实际状态，不弱化失败。

## 不充分的证据

- “代码看起来正确”。
- 只通过 lint，却声称构建或测试通过。
- 只通过单元测试，却声称端到端行为通过。
- 使用修改前、其他分支或其他 Agent 的测试结果。
- 测试通过，但没有核对需求、迁移、OpenAPI 或安全边界。

## 仓库尚未初始化时

如果 `make check` 或具体工具尚不存在：

- 运行当前可用的最接近检查。
- 明确列出缺失的验证能力。
- 使用“未能验证”而不是“应该通过”。
- 不为制造绿色结果而跳过、删除或放宽测试。

## 最终报告格式

```text
变更：实际完成的内容
验证：命令及通过/失败结果
未验证：无法执行的检查及原因
风险：仍需人工确认或后续处理的事项
```
